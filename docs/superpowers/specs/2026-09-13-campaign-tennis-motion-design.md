# 캠페인용 2.5D 테니스 동작 설계

## 목표

`games/tennis-visual-2d`를 캠페인 페이지에 삽입할 수 있는 짧고 직관적인 테니스 게임으로 개선한다. 플레이어는 한 번의 스와이프로 서브 방향과 세기를 정하며, 캐릭터는 준비 자세부터 토스, 타격, 팔로스루, 복귀까지 자연스럽고 연속적인 동작을 수행한다.

완성 기준은 다음과 같다.

- 첫 조작을 별도 설명 없이 이해할 수 있다.
- 서브 공이 캐릭터의 손에서 출발하고 라켓의 타격 프레임과 정확히 만난다.
- 캐릭터의 발 이동, 스윙, 공의 비행이 하나의 타임라인처럼 연결된다.
- 모바일 세로 화면과 데스크톱 화면 모두에서 코트와 캐릭터가 잘리지 않는다.
- 한 포인트가 빠르게 진행되고, 한 게임은 약 30~60초에 끝난다.

## 범위

이번 변경은 `games/tennis-visual-2d`만 대상으로 한다. 기존 `tennis-3d`와 `tennis-playcanvas`는 비교용 프로토타입으로 유지하며 삭제하거나 수정하지 않는다.

포함 범위:

- 한 번의 드래그/스와이프로 조준하는 서브
- 자연스러운 서브 동작 상태 머신
- 공과 라켓 접점 동기화
- 랠리 시 자동 위치 보조와 포핸드/백핸드 연결
- 모바일 터치와 데스크톱 포인터 입력 통합
- 조준선, 착지 마커, 타격 파티클, 화면 충격 연출
- 화면 비율별 카메라·코트 배치

제외 범위:

- 실제 테니스 규칙 전체와 세트 시스템
- 온라인 멀티플레이
- 캐릭터 성장 및 아이템
- Rapier, Havok 같은 범용 물리엔진 도입
- 최종 브랜드 캐릭터 원화 및 사운드 에셋 제작

## 플레이 흐름

### 서브

1. 캐릭터가 베이스라인에서 준비 자세를 취한다.
2. 사용자가 화면을 누르고 반대 코트 방향으로 드래그한다.
3. 드래그 중 예상 궤적과 착지 지점을 표시한다.
4. 사용자가 손을 놓으면 조준값을 확정하고 서브 전체 동작을 시작한다.
5. 캐릭터가 무릎을 굽히며 공을 든 팔을 올린다.
6. 공이 손 위치에서 떠오르는 동시에 라켓 백스윙과 상체 회전이 시작된다.
7. 공이 정점 부근에 도착할 때 캐릭터가 점프하고 라켓이 공에 닿는다.
8. 타격 프레임에서만 공의 상태를 `toss`에서 `flight`로 전환한다.
9. 캐릭터가 팔로스루와 착지를 수행한 뒤 랠리 준비 자세로 복귀한다.

사용자는 토스와 타격을 따로 입력하지 않는다. 조작 실패 대신 스와이프의 방향과 길이에 따라 정확도와 파워가 달라진다.

### 랠리

- 공이 플레이어 코트로 날아오면 예상 타격 위치를 계산한다.
- 캐릭터는 타격 지점 근처까지 자동으로 이동한다.
- 사용자는 다음 샷의 방향을 드래그해 정한다.
- 공의 도착 시간에 맞춰 준비 동작을 시작하고, 도착한 공의 좌우 위치에 따라 포핸드 또는 백핸드를 선택한다.
- 입력이 없으면 중앙에 가까운 안전한 자동 리턴을 수행한다.
- 너무 늦은 입력은 아웃 확률과 약한 타격으로 반영하되, 캐릭터가 허공을 치는 장면은 최소화한다.

## 동작 모델

캐릭터 동작은 임의의 GSAP 호출 모음이 아니라 명시적인 상태 머신으로 관리한다.

```text
serveReady
  -> serveAim
  -> serveToss
  -> serveLoad
  -> serveContact
  -> serveFollowThrough
  -> rallyReady
  -> moveToBall
  -> forehand | backhand
  -> recover
```

서브 기준 타이밍:

- 준비 및 무릎 굽힘: 180ms
- 토스 시작부터 정점까지: 620ms
- 백스윙과 상체 회전: 토스 시작 120ms 후부터 정점까지
- 점프와 타격: 정점 90ms 전부터 시작, 정점 20~50ms 후 접촉
- 팔로스루: 320ms
- 착지 및 랠리 자세 복귀: 260ms

각 상태는 정규화된 진행률 `0..1`을 노출한다. 캐릭터 포즈, 손 위치, 라켓 접점과 공의 위치는 같은 진행률을 사용한다. 프레임 속도가 달라도 접점이 어긋나지 않도록 타임라인은 누적 실시간이 아니라 고정 스텝 게임 시간으로 갱신한다.

## 캐릭터 표현

초기 구현은 PixiJS 컨테이너로 구성한 관절형 2D 리그를 사용한다. 몸통, 머리, 상·하완, 허벅지, 종아리, 라켓을 각각 피벗 가능한 부품으로 나눈다. 이를 통해 임시 도형 캐릭터라도 실제 테니스 동작의 무게 중심과 팔로스루를 확인할 수 있다.

최종 브랜드 캐릭터 스프라이트가 준비되면 상태 머신과 접점 이벤트는 유지하고 렌더러만 스프라이트 시트 기반으로 교체한다. 게임 규칙이 특정 캐릭터 그림에 의존하지 않도록 `CharacterAnimator` 인터페이스 뒤에 렌더링 구현을 둔다.

## 공 이동과 접점

공은 코트 평면의 `x`, `y`와 높이 `z`를 가진 단순 상태로 관리한다. Matter.js 바디와 별도의 높이 변수를 섞지 않고 하나의 결정적 시뮬레이션으로 통합한다.

- 토스 중에는 손의 월드 위치에서 출발한 포물선을 따른다.
- 타격 전까지 공은 캐릭터 동작 타임라인에 귀속된다.
- `serveContact` 이벤트에서 라켓 접점과 공 사이의 거리를 검사한다.
- 접점이 허용 범위 안이면 목표 착지점과 비행 시간을 이용해 초기 속도를 계산한다.
- 바운드, 네트 통과 높이, 코트 아웃 판정은 고정 스텝으로 계산한다.
- 랠리 타격 역시 목표 착지점 기반 포물선을 사용해 캠페인 게임에 필요한 조작 안정성을 확보한다.

Matter.js는 제거한다. 이번 게임에서 필요한 것은 범용 강체 충돌이 아니라 재현 가능한 공 궤적과 애니메이션 동기화다.

## 입력

포인터 이벤트 하나로 마우스와 터치를 지원한다.

- `pointerdown`: 조준 시작
- `pointermove`: 드래그 벡터와 착지 예상 지점 갱신
- `pointerup`: 방향과 파워 확정, 서브 또는 리턴 실행
- `pointercancel`: 조준 취소, 기존 준비 상태 유지

드래그가 너무 짧으면 기본 중앙 안전 샷을 사용한다. 조준 벡터는 코트 좌표로 변환한 뒤 유효 영역으로 제한한다. 입력 중 페이지 스크롤이 발생하지 않도록 게임 캔버스에만 `touch-action: none`을 적용한다.

키보드는 개발과 접근성 보조 입력으로 유지한다. 방향키는 목표 지점을 조정하고 Space는 현재 조준값으로 샷을 실행한다.

## 화면과 연출

- 코트는 고정 원근 투영을 사용하되 화면 비율에 따라 가상 카메라의 중심과 확대율을 조정한다.
- 세로 화면에서는 가까운 플레이어를 크게 보여주고 UI를 코트 바깥 여백에 배치한다.
- 조준 중에는 곡선 궤적과 반대편 코트의 착지 원을 표시한다.
- 타격 순간 60~90ms 히트 스톱, 짧은 카메라 펀치, 공 속도선과 파티클을 적용한다.
- 공 그림자는 높이에 따라 작고 흐려져 공중 높이를 즉시 읽을 수 있게 한다.
- 점수와 CTA는 React UI에 남기고 매 프레임 위치는 PixiJS가 관리한다.

## 코드 구조

기존 클래스를 다음 책임으로 정리한다.

- `VisualTennisGame`: 경기 상태와 각 시스템의 조정
- `CharacterController`: 상태 전환, 타격 위치 예측, 자동 이동
- `CharacterAnimator`: 상태 진행률을 시각적 포즈로 변환
- `BallSimulation`: 토스, 비행, 바운드와 네트 판정
- `AimController`: 포인터 드래그를 코트 목표와 파워로 변환
- `CourtProjection`: 코트 좌표를 반응형 화면 좌표로 변환
- `GameEffects`: 궤적, 착지 마커, 히트 스톱, 파티클

React에는 선택 화면, 점수, 캠페인 메시지와 결과 CTA만 둔다. 게임 루프 상태를 React state로 매 프레임 전달하지 않는다.

## 오류와 복구

- 포인터가 캔버스 밖에서 해제되면 `pointercancel`과 동일하게 처리한다.
- 탭이 백그라운드로 이동하면 게임 시간을 일시 정지해 복귀 시 공이 순간 이동하지 않게 한다.
- 비정상적인 긴 프레임은 최대 델타를 제한하고 고정 스텝 반복 횟수에 상한을 둔다.
- 화면 크기가 0이거나 지나치게 작을 때는 렌더링을 일시 중지하고 안내 UI를 표시한다.
- 접점 오차가 발생하더라도 캠페인 모드에서는 허용 반경 안의 공을 라켓 위치로 보정한 뒤 정상 비행시킨다.

## 테스트와 검증

단위 테스트:

- 드래그 벡터가 유효한 코트 목표와 파워로 변환되는지 검증
- 서브 타임라인의 상태 순서와 접촉 이벤트가 한 번만 발생하는지 검증
- 서로 다른 프레임 간격에서도 토스 정점과 접촉 시각이 허용 오차 안인지 검증
- 목표 착지점을 기준으로 계산한 공이 허용 범위 안에 바운드하는지 검증
- 화면 비율별 투영 결과가 안전 영역 안에 들어오는지 검증

브라우저 검증:

- 모바일 세로 390x844
- 모바일 가로 844x390
- 데스크톱 1440x900
- 마우스 드래그, 단일 터치, 포인터 취소
- 최소 10회의 연속 서브에서 공과 라켓이 시각적으로 분리되지 않는지 확인
- 서브부터 첫 랠리 복귀까지 캐릭터가 순간 이동하거나 기본 자세로 튀지 않는지 확인

## 구현 순서

1. 상태 머신과 공 시뮬레이션을 순수 TypeScript로 작성하고 테스트한다.
2. 관절형 캐릭터 리그와 서브 타임라인을 연결한다.
3. 스와이프 조준과 착지 마커를 연결한다.
4. 랠리 자동 이동과 포핸드/백핸드를 연결한다.
5. 반응형 투영과 모바일 UI를 조정한다.
6. 히트 스톱, 파티클, 화면 펀치를 추가한다.
7. 실제 브라우저에서 세 화면 크기와 터치 흐름을 검증한다.
